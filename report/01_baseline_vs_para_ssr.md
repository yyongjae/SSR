## 1. 요약

| | L2 MAX avg (m) ↓ | CR box avg (%) ↓ | 판정 |
|---|---|---|---|
| SSR 논문 Table 3 (w/o FFP) | 0.75 | 0.20 | 목표 |

- PARA-SSR의 열세는 구현 버그가 아니라 **shared BEV에 대한 gradient 배분 실패 + aux task 2개의 학습 실패**가 원인이다 (§5, §6).
- SSR 저자들도 Appendix E Table 6에서 PARA-Drive식 병렬 aux를 붙였을 때 planning이 나빠지는 것을 이미 보고했다 (L2 0.75→0.79~0.86). 즉 방향 자체는 예견된 난점이었고, 우리 실험은 **그 열화 폭이 왜 그렇게 큰지**를 정량화한 데 의미가 있다.

## 5. Gradient norm 분석 ★

`ParaSSR`에 심어둔 진단 훅이 200 iter마다 `‖∂L_task/∂bev_embed‖`(gnorm)와 그 정규화 비율(gshare)을 기록한다. 이것이 이번 실험에서 가장 정보량이 큰 신호였다.

### 5.1 gnorm — task별 BEV gradient 크기 (절대값)

| ep | plan | det | map | occ |
|---:|---:|---:|---:|---:|
| 1 | 0.002 | 0.093 | 0.001 | 0.001 |
| 2 | 0.007 | 0.105 | 0.001 | 0.009 |
| 3 | 0.009 | 0.102 | 0.007 | 0.011 |
| 4 | 0.007 | 0.109 | 0.014 | 0.014 |
| 6 | 0.007 | 0.115 | 0.020 | 0.018 |
| 9 | 0.008 | 0.129 | 0.026 | 0.019 |
| 12 | **0.007** | **0.118** | **0.027** | **0.019** |

- **plan의 gnorm은 ep2 이후 0.007에서 고정**이다. 학습 내내 한 번도 커지지 않았다.
- det는 처음부터 0.09~0.13으로 **planning의 15~17배**.
- map/occ는 0.001에서 시작해 ep4~6에 planning을 추월하고 계속 커진다.

**해석 3가지:**

**(a) planning은 처음부터 끝까지 소수파였다.** 최고치가 ep3의 8.2%, 최종 4.7%. 나머지 95%를 aux가 가져갔다. SSR의 planner는 16개 scene token만 보고 궤적을 만드는 구조라 BEV를 "적게, 그러나 정확하게" 읽어야 하는데, BEV 자체가 다른 task에 맞춰 형성되어 버렸다.

**(b) epoch 4에서 planning이 밀려났다.** ep3에 8.2%까지 올라갔던 planning share가 ep4에 5.5%로 급락한다. 원인은 planning이 약해져서가 아니라(gnorm은 0.009→0.007로 거의 그대로) **map이 0.007→0.014로 2배가 되며 밀어냈기** 때문이다. §4.1의 곡선 분기점(ep4)과 정확히 일치한다.

**(c) 총 grad_norm이 baseline의 49배다.**

| ep | grad_norm (PARA) | grad_norm (baseline) | 배율 |
|---:|---:|---:|---:|
| 1 | 21.65 | 1.25 | 17× |
| 6 | 35.71 | 0.92 | 39× |
| 12 | **38.54** | **0.78** | **49×** |

방향이 반대라는 점이 중요하다. baseline은 수렴하며 gradient가 줄어드는(1.25→0.78) 정상 거동인데, PARA-SSR은 계속 커진다(21.7→38.5). 공유 파라미터가 받는 총 업데이트 크기가 학습 후반으로 갈수록 aux에 지배되며, AdamW의 per-parameter 정규화가 있어도 **backbone/encoder가 planning과 무관한 방향으로 계속 재편**된다.

### 5.3 학습된 체크포인트에서의 gradient 방향 측정

epoch 12 체크포인트에 대해 `bev_embed`에서 task별 gradient의 코사인 유사도를 직접 쟀다:

| 쌍 | cos |
|---|---|
| (plan, det) | **−0.0003** |
| (plan, map) | **+0.0004** |
| (plan, occ) | **−0.0001** |

전부 ~0이다. **이것이 진단의 핵심이다.**

- 음수였다면 → aux가 planning을 **방해**하는 것 → PCGrad/GradDrop 같은 gradient surgery가 처방.
- 관측된 ~0 → aux가 planning과 **무관한 방향**으로 BEV를 끌고 감 → **희석(dilution)**. 처방은 **크기 재조정**.

즉 "aux가 planning을 망친다"가 아니라 "**aux가 planning의 자리를 빼앗는다**"가 맞는 서술이다.

## 6. Aux head 품질 (epoch 12, 60 샘플, threshold sweep)

> **정정 (2026-08-17).** 초판은 threshold 0.5 한 점에서만 재고 "map/ped-occ가 완전히
> 죽었다(IoU 0.003 / 0.005)"고 썼다. UniAD는 BEV occupancy를 `test_seg_thresh=0.1`로
> 평가하므로 0.5는 이 계열의 표준 동작점이 아니다. 전 threshold를 다시 재고 GT 양성
> 비율도 실측했다. **결론의 방향은 유지되지만 원인 설명이 바뀐다.**

|---|---:|---:|

### 6.3 실제 실패 형태 — 공간 분별력 상실 ★

| 채널 | GT 양성률 | mean p (GT 양성) | mean p (GT 음성) | **분별비** |
|---|---:|---:|---:|---:|
| occ vehicle | 15.50% | 0.6918 | 0.0886 | 7.8× |
| occ pedestrian | 0.162% | 0.0519 | 0.00042 | **124×** |
| map divider | 8.18% | 0.1154 | 0.0702 | **1.6×** |
| map ped_crossing | 1.82% | 0.0548 | 0.0128 | 4.3× |
| map boundary | 9.95% | 0.3024 | 0.2862 | **1.06×** |

**boundary는 전 픽셀에 거의 같은 값(≈0.29)을 출력한다.** thr ≤ 0.2에서 10,000픽셀 전부를 양성으로 예측하고, 그때 IoU 0.0995는 정확히 GT 양성률(9.95%)과 같다 — **"전부 양성"이라고 답했을 때의 IoU**다. 학습된 것이 없다는 뜻이다. divider도 분별비 1.6×로 사실상 무의미하다.

반면 occ pedestrian은 분별비 **124×로 vehicle(7.8×)보다도 상대적 분별력이 좋다.** 절대 확률이 낮을 뿐이다.

→ **두 실패는 원인이 다르다.**
> - **map (dense)**: 위치를 못 찾는다. 공간 분별력 자체가 없다.
> - **ped-occ**: 위치는 찾는데(124×) 확률 수준이 낮고, 80%는 아예 놓친다.
>
> 초판의 "둘 다 극단적 under-confidence"는 틀렸다.

### 6.4 확률 수준을 결정하는 것: top-k BCE의 균형점

`OccBinarySegmentationLoss(use_top_k=True, top_k_ratio=0.25)`는 픽셀별 BCE 중 **손실 상위 k=2,500개**만 평균한다. 양성 픽셀은 거의 항상 상위 k에 들어가므로 균일 예측자의 균형점은

```
p* = (프레임당 GT 양성 픽셀 수) / k = n_pos / 2500
```

| 채널 | n_pos | **예측 p\* = n_pos/2500** | 실측 mean p (GT 양성) |
|---|---:|---:|---:|
| occ vehicle | 1550 | **0.620** | 0.692 ✓ |
| occ pedestrian | 16 | **0.0064** | 0.052 ✓ (8× 상회) |
| map boundary | 995 | **0.398** | 0.302 ✓ |
| map ped_crossing | 182 | **0.073** | 0.055 ✓ |
| map divider | 818 | 0.327 | 0.115 (dice가 끌어내림) |

**6개 채널 중 5개에서 예측이 맞는다.** 각 채널의 출력 확률 수준은 학습 품질이 아니라 **그 클래스의 GT 밀도**가 결정한다.

- vehicle은 p\*=0.62라 threshold 0.5를 자연스럽게 넘는다.
- pedestrian은 p\*=0.0064다. **0.5를 넘으려면 균형점의 78배로 과확신해야 하고, 이 손실 함수 아래서는 학습을 아무리 오래 해도 불가능하다.**

## 7. SSR 고유 손상: TokenLearner 붕괴

SSR은 BEV를 **16개 scene token**으로 압축한 뒤 planner에 넘긴다 (논문 Eq.4-6). 이 병목의 상태를 두 체크포인트에서 비교했다:

| 지표 | baseline | PARA-SSR | 변화 |
|---|---:|---:|---|
| 토큰 간 pairwise 유사도 | 0.209 | **0.341** | **+63%** |
| attention map 엔트로피 | 8.079 | 7.941 | −1.7% |
| top-100 attention mass | 0.263 | 0.290 | +10% |
| BEV feature std | 0.990 | 0.974 | −1.6% |
| BEV feature norm | 15.84 | 15.59 | −1.6% |

**BEV feature 자체의 통계는 사실상 동일하다** (std/norm −1.6%). 그런데 **16개 token이 서로 63% 더 중복되게 변했다.**

SSR의 전제는 "16개 token이 각각 다른 영역/의미를 담당한다"는 것이다 (논문 Fig.10의 token attention 시각화). 토큰이 중복되면 planner가 실제로 받는 정보의 rank가 줄어든다. 극단적으로 모든 토큰이 같아지면 16개가 아니라 1개짜리 요약을 보는 셈이다.

**이것이 "학습 loss 격차(29%) < 평가 격차(36~52%)"를 설명한다.** 단순히 덜 최적화된 것이라면 두 격차가 비슷해야 한다. 표현 자체가 손상되면 학습 분포에서는 어느 정도 보완되지만 평가에서 더 크게 벌어진다.

## 8. 종합 진단

세 가지 원인이 겹쳤다. 중요도 순:

### 원인 1 — Gradient 희석 (구조적)
planning이 BEV gradient의 4.7%만 확보. aux는 planning과 직교(cos≈0)하므로 방해가 아니라 **잠식**. 이건 PARA-Drive를 SSR에 붙일 때 필연적으로 생기는 문제다. PARA-Drive의 planner는 dense BEV를 직접 cross-attend하지만, SSR의 planner는 16 token 병목을 통과하므로 **BEV 품질 변화에 훨씬 민감**하다.

### 원인 2 — 죽은 aux 신호 2개 (구현 결함, 내 책임)
map(IoU 0.003)과 ped-occ(IoU 0.005)가 학습에 실패했는데도 각각 **17.7% / 12.4%(occ 절반)의 BEV gradient를 소비**했다. 학습되지 않는 head의 gradient는 공유 표현 입장에서 **거의 노이즈**다. 잘 학습된 task가 같은 비중을 갖는 것보다 훨씬 해롭다.

원인:
- 100×100 격자에 1~2셀 두께 폴리라인 → 조금만 어긋나도 IoU 0
- 클래스 불균형 미처리 (BCE에 pos_weight 없음, top-k 25%로는 부족)
- 0.41M conv 3층 head — PARA-Drive는 Panoptic SegFormer 사용
- ped-occ: 어떤 주요 E2E 논문도 BEV에서 보행자 occupancy를 별도 채널로 예측하지 않음 (UniAD/FIERY/ST-P3 모두 vehicle-only)

### 원인 3 — TokenLearner 다양성 붕괴 (SSR 고유)
토큰 유사도 +63%. 원인 1·2의 **결과**이면서 동시에 성능 저하를 **증폭**시키는 경로다. loss weight만 조정해서는 직접 잡히지 않을 수 있다.

## 9. 개선 방향 (우선순위)

### P0 — 죽은 신호 제거/수리
- **occ에서 pedestrian 채널 제거** → vehicle 단일 채널(IoU 0.586)만 유지. 즉시 적용 가능, 비용 0.
- **map을 VAD 벡터 헤드로 교체** → 보고서 #02 참조. VAD에서 학습성이 검증된 표현.
- (대안) PARA-Drive Table 5는 map 모듈 제거 시 L2/CR이 거의 변하지 않고 map-compliance만 나빠진다고 보고 → map 완전 제거도 유효한 선택지.

### P1 — 측정값 기반 gradient 재조정
현재 plan share = 4.06%. 목표 share **X**에 필요한 `aux_grad_scale`:

```
s = 0.0406 · (1/X − 1) / 0.9594

  X = 0.30  →  s ≈ 0.10
  X = 0.50  →  s ≈ 0.042
```

현재 `PARA_SSR_w_gradscale.py`의 **s=0.02는 plan share ~68%를 겨냥하는 과교정**이다. **0.1 / 0.04** 두 값으로 sweep 권장.

### P2 — token diversity 정규화 (SSR 특화)
16개 token attention map의 pairwise 유사도에 페널티를 추가. §7에서 측정된 실패 지점을 직접 겨냥하며 구현이 수 줄이다.

### P3 — aux warmup
ep1에 det이 95.4%를 점유하며 BEV 초기 형태를 결정해버린다. 첫 2~3 epoch 동안 aux 가중치를 0→1로 램프업.

### P4 — task별 BEV adapter (KD 목적)
각 aux head 앞에 전용 conv adapter를 두어 공유 trunk가 받는 aux gradient를 필터링. **teacher 품질과 BEV 보호를 분리**할 수 있어 KD 실험에 특히 유용.

### 다음 실험 (정보량 순)
| ID | 구성 | 확인하려는 것 |
|---|---|---|
| E1 | occ(vehicle only) + det, map 제거, `aux_grad_scale=0.1` | 잘 배우는 신호만 남기고 적절히 눌렀을 때의 상한 |
| E2 | E1 + token diversity 정규화 | §7 손상이 독립 원인인지 |
