# 가정 장부 — 무엇을 믿고 무엇을 쟀나

지금까지 세운 가정을 판정 전에 고정해 둔다. 결과가 나오면 이 표의 "판정" 칸만 채운다.
측정 기준은 하나로 고정: **채점기가 고른 앵커의 실제 점수(공식 채점기 라벨)**. 순위 AUC는 보조 지표로만 쓰고,
서로 다른 기준의 숫자를 같은 표에 올리지 않는다(이전에 그 실수를 했다).

| # | 가정 | 근거로 삼을 측정 | 현재 상태 |
|---|---|---|---|
| H1 | v2 의 손실은 인지 성능이 아니라 인지를 채점에 쓰지 않는 데서 온다 | 개입 진단: 차량을 det token + BEV 에서 동시에 제거했을 때 NC 예측 변화 | 확인. v2 +0.04 (위약 0.001), entity critic +0.11~0.17 |
| H2 | 앵커 집합은 병목이 아니다 | navtrain 라벨 10만 장면의 앵커 상한과 안전 앵커 개수 | 확인. 상한 93.64, 안전 4지표 만점 앵커 장면당 57개, 없는 장면 0.1% |
| H3 | 남은 손실의 대부분은 쓰기(offset)가 아니라 고르기다 | 상위 3 기준 앵커/refined 상한, 그리고 전 후보 refined 라벨 | 부분 확인 (상위 3: 91.07 / 91.57). 전 후보 refined 라벨 대기 |
| H4 | 대상 token 만 보는 critic 이 v2 보다 잘 고른다 | held-out 장면에서 고른 앵커의 실제 PDMS | navtrain held-out 에서 83.24 vs 79.15. navtest 재확인 대기 |

| H8 | 채점 대상(앵커)과 주행 대상(refined)의 불일치가 실제 손해다 | 전 후보를 refine 해 채점, 앵커 기준 최선과 refined 기준 최선의 불일치율 | 라벨링 대기. 현재 간접 증거: DAC AUC 0.904 → 0.808 |
| H9 | GT critic 의 우위 중 일부는 센서로 보이지 않는 대상 덕분이다 | critic(GT) − critic(pred) 차이, mixed 학습과의 비교 | pred/mixed critic 결과 대기 |

## 판정이 갈리는 지점

- H5 가 참이면: 증류로 옮길 실체가 있다 (인지 → 채점의 연결을 가르치는 문제).
- H5 가 거짓이고 H4 만 참이면: 우위의 정체는 "완벽한 인지"이지 "읽는 법"이 아니다. 그때는 GT critic 을 teacher 로 쓰는
  기여는 약해지고, 대신 H8(채점-주행 불일치) 쪽이 남는다.
- H6 가 뒤집히면(navtest 에서 격차가 사라지면) H4 는 held-out 착시였다는 뜻이므로 방향 자체를 접는다.

## 기준 정정 (2026-09-20 14:55)

평가 기준을 공식 EPDMS 로 통일한다. 그전까지 채점기 비교에 쓰던 WoTE navtrain 라벨은 **학습 타깃**이지
평가 척도가 아니었다. 그 라벨의 ego_progress 는 같이 채점한 256개 후보 중 최대 진행도로 정규화된 값이고
(`pdm_scorer._calculate_progress`: `norm_constant_progress = np.max(masked_progress)`), 공식 평가는
`[PDM planner, 궤적]` 둘만 채점하므로 분모가 다르다. navtrain 에는 metric cache 가 없어 공식 채점을
돌릴 수 없었고, 있는 라벨을 그대로 쓴 것이 잘못이었다.

- 버린 수치: navtrain held-out 의 79.15 / 83.24 / 79.55 / 93.61 (학습 진단용으로만 남김)
- 쓰는 수치: navtest 앵커·refined 라벨. 공식 평가 csv 와 장면별 차이 **0.0000** 으로 검증했다
  (단 EC 제외. EC 는 이전 프레임의 선택된 궤적이 필요해 후보별 라벨로 정의되지 않는다).
- 학습 타깃은 그대로 WoTE 라벨을 쓴다. v2 의 점수 head 도 같은 타깃으로 학습했고 선행연구(Hydra-MDP 계열)의
  관례와 같다. 어긋났던 것은 평가 쪽뿐이다.

## navhard 에서 같은 비교를 하려면 (미리 확인한 제약)

navhard 두 단계 평가는 stage one 부터 **reactive** traffic agents 를 쓴다
(`run_pdm_score_two_stage_gpu.py`: `instantiate(cfg.traffic_agents_policy.reactive, ...)`).
reactive 환경은 자차의 시뮬레이션 상태에 따라 달라지므로, navtest 에서 쓴 "256개를 한 배치로 채점"이
navhard 에서는 성립하지 않는다 — 후보마다 환경을 따로 굴려야 하고 비용이 256배가 된다.
navhard 로 확장할 때는 이 경로를 그대로 따르거나(비용 감수), 장면 수를 줄여야 한다. 임의로 non-reactive 로
바꿔 재는 것은 공식 기준이 아니므로 하지 않는다. navtest 공식 평가가 non_reactive 인 것은 실행 설정
(`traffic_agents: non_reactive`)과 장면별 0.0000 일치로 확인했다.

## 공식 기준 판정 (2026-09-20 16:00, navtest 12,146 장면, EC 제외 EPDMS)

검증: 내 라벨의 앵커 r1 점수 = 공식 평가 csv (EC 제외) 장면별 차이 0.0000.
v2 의 선택식 재현: 내 구현이 plan_final_rewards 의 선택을 99.5% 재현, 점수 86.49 동일.

| sim 점수 출처 (선택식은 v2 와 동일) | EPDMS |
|---|---|
| v2 자신의 채점 head (배포) | 86.49 |
| critic(GT 학습) + GT 인지 | **87.99** |
| critic(mixed) + GT 인지 | 87.68 |
| critic(mixed) + v2 예측 인지 | 85.14 |
| critic(pred 학습) + v2 예측 인지 | 85.26 |
| 정답을 아는 선택 (상한) | 98.48 |
| 사람 / NAVSIM PDM planner | 95.33 / 92.30 |

- **H4 참(약함)**: 완벽한 인지를 가진 entity 채점기가 +1.5. 상한 12점 중 1.5점.
- **H5 거짓**: v2 자신의 검출·맵을 넣으면 −1.2. entity token 으로 뽑는 순간 BEV 가 가진 정보를 잃는다.
- 인지 오류가 채점에 물리는 비용 = 87.99 − 85.14 = **2.85점**.
- 주의: 선택식을 맞추지 않으면(critic 의 5개 sub-score 만으로 고르면) critic 이 LK·HC 에서 크게 잃어
  총점이 뒤집힌다. LK·HC 는 critic 의 학습 타깃에 없다. 조건을 맞추지 않은 표로 "사망" 이라고
  결론 내렸다가 정정했다.

**재순위 실험 (H: 상위 3 안의 3.8점을 예측 가능한가) — 전부 실패.**
점수/기하/실행(TOAD 역기구학)/인지 어떤 조합도 1순위(86.26)를 넘지 못했다(회복률 −1.8% ~ −11.4%,
상한 92.27). 지금 가진 입력으로 그 격차는 예측 불가능하다.

## 선행연구 조사 결과 (H8 관련, 2026-09-20)

- WoTE 는 이 불일치를 **논문에 명시**한다: "학습 때는 anchor 를 evaluation module 에 넣고, 테스트 때는
  refined trajectory 를 평가한다." 그리고 Table 7 에서 "refined 를 쓰면 오히려 더 좋다"며 넘어간다.
- TOAD 는 일반 원리를 이미 서술: 고정 vocabulary 로만 학습한 채점기는 그 집합 밖에서 제대로 동작할 이유가 없다.
- DiffusionDriveV2(2025.12) 는 mode selector 를 자기 모델의 refined 출력 99% + 고정 vocabulary 1% 로 학습한다.
  "자기가 모는 궤적으로 채점기를 학습"의 일회성 버전은 이미 구현되어 있다.
- 「Designing Versatile Samples」(2609.01799) 는 "고른 것과 자기 후보 중 최선의 격차"를 명시적으로 지목한다.
  우리의 상위 3 오라클 격차는 발견으로서 새롭지 않다.
- 남은 틈: 학습이 진행되며 반복 재시뮬레이션하는 DAgger 식 on-policy 라벨링은 NAVSIM 채점기 학습에 없다.
