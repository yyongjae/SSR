## 1. 용어 사전

### 1-1. 모델과 데이터

| 용어 | 뜻 |
|---|---|
| **E2E planner** | 센서 입력에서 주행 궤적까지 한 모델로 내는 자율주행 모델 |
| **PARA-SSR** | 우리 camera-only E2E 모델이다. 카메라 → 조감도(BEV) → 검출·모션·지도·계획 head. 이 문서의 기본 모델은 **v1(`interaction_final`)**, navtest PDMS 84.87(0.8487, 30 epoch `last.ckpt`)이다. kyungmin님의 v2(anchor 256개 + 점수 head, PDMS 88.14)는 이번 실험에 포함하지 않는다 |
| **조감도(BEV)** | 차량 주변을 위에서 내려다본 격자 feature다. 여기서는 50×100칸, 한 칸 0.64 m, 전방 0–32 m, 좌우 ±32 m. 행은 전방 거리, 0번 열이 왼쪽 32 m다(S grid) |
| **aux teacher** | student에 없는 정보를 쓰는 큰 모델 |
| **BEVFusion (det teacher)** | LiDAR+카메라 3D 검출 모델. 조감도 feature(256채널)를 캐시해 두고 쓴다. navtrain으로 학습된 것으로 기록돼 있다(이번에 다시 확인하지는 않음) |
| **ReSMap (map teacher)** | 카메라+위성 영상 온라인 HD 지도 모델(도로·보도·중앙선·횡단보도). 조감도 feature(256채널, 같은 격자)를 캐시해 두고 쓴다. **navtrain 쪽 캐시는 train_logs만 담는다**(navtest 캐시는 따로 있음) |
| **초안 (draft, τ0)** | 교정기에 들어가는 "고칠 대상" 궤적이다. 0.5초 간격 8점, 4초. 단계 T에서는 사람 궤적을 일부러 망가뜨린 것이고, 단계 E에서는 PARA-SSR 출력 또는 망가뜨린 GT 궤적이다 |
| **교정기 (refiner)** | 초안을 받아 **교정량**을 내는 작은 모델(약 340만 파라미터). §3 참고 |
| **R_T / R_M / R_none / R_TM** | 입력만 다른 교정기들이다. teacher 조감도는 R_T가 BEVFusion, R_M이 ReSMap, R_TM이 둘 다를 읽고, R_none은 장면을 보지 않는다. 몸통 구조는 모두 같다 |
| **R_S** | 원래 설계(report 36)에서 **학습이 끝난 student의 조감도**를 읽는 단계 T 교정기. 학습된 E2E 모델이 필요해서 뺐다(§4-2). 단계 E 코드에서는 student 교정기를 R_S라고도 부른다 |
| **student 교정기** | 단계 E에서 PARA-SSR에 붙이는 교정기. **PARA-SSR 자신의 카메라 조감도**를 읽는다 |
| **GT** | 학습 데이터에만 있는 정답이다. 주변 물체의 실제 미래 움직임, 실제 도로 지도, 사람이 실제로 간 궤적 |
| **GT 벌점 (surrogate)** | 고친 궤적을 GT 위에 놓고, 공식 채점 항목을 미분 가능하게 흉내 낸 벌점. §5 참고 |
| **KD** | 고정된 teacher 교정기의 교정량을 student 교정기가 따라 배우게 하는 loss. §8-4 참고 |
| **navtrain / navtest** | NAVSIM 공식 학습·테스트 split. navtest는 12,146장면이다(단계 T 평가는 frame gap 45장면을 뺀 12,101장면) |
| **train_logs / val_logs** | navtrain을 이루는 두 log 묶음. NAVSIM 설정 파일(`default_train_val_test_log_split.yaml`) 기준이다. PARA-SSR은 train_logs 85,109장면으로 학습한다 |
| **장면 (token)** | NAVSIM 샘플 하나. 한 시점의 센서와 과거 1.5초, 미래 5초 |
| **log와 drive** | **drive**는 한 차량이 한 번 출발해 달린 긴 주행(같은 날·같은 차량·같은 시작 시각)이다. **log**는 drive를 잘라 만든 구간이다. 예: `2021.10.06.08.34.20_veh-53_00020_00165`와 `..._00179_00244`는 같은 drive의 두 log다. 그래서 "log 단위로 분리"해도 같은 drive의 이웃 구간이 양쪽에 있을 수 있다(§6-1) |
| **train / dev / OOF fold / inner-val** | 단계 T에서 쓴 데이터 구분이다(§6-1). dev는 판정용 held-out validation, navtest는 최종 test다 |
| **OOF (out-of-fold)** | 학습 풀을 log 단위로 5조각 낸 것 중 **학습에 쓰지 않은 조각 0**. θ 선택과 감속 생존율 확인에만 쓴다 |
| **inner-val** | 학습 조각(1–4)의 10%를 떼어 조기 종료에만 쓰는 세트 |

### 1-2. 점수와 단위

| 용어 | 뜻 |
|---|---|
| **PDMS** | NAVSIM(v1) 공식 점수. NC·DAC·DDC·(5·EP + 5·TTC + 2·C)/12. 장면마다 0–1이다 |
| NC | 과실 충돌 없음 |
| DAC | 주행 가능 영역 준수 |
| DDC | 주행 방향 준수 |
| TTC | 0.3·0.6·0.9초 앞으로 투영했을 때 충돌 임박 없음 |
| EP | 진행 정도 |
| C | 승차감 |
| **EPDMS** | NAVSIM v2 채점기의 확장 PDMS(report 29). 단계 T에서는 수정 7로 뺐다. §2-4의 kyungmin feasibility 수치(EPDMS +0.33)는 이 척도다 |
| **PDMS의 세 가지 쓰임** | ① **모델 점수:** E2E 모델 궤적의 navtest 평균, 보통 ×100으로 적는다(E0 84.87). ② **단계 T 점수:** 합성 초안(장면당 13개)을 교정한 뒤의 평균, 0–1 척도(예: 0.896). ③ **점(point):** 단계 T 차이 P1은 0–1 PDMS 차 ×100이다(+1.44점 = +0.0144). ①과 ②는 비교할 수 없다 |
| **%p (pp)** | 실패율의 차. 예: 1.95% → 1.43%는 0.52%p 감소 |
| **교정량의 단위** | 감속은 m/s(초안 속도에서 뺄 양), 옆 이동은 m(초안 경로에서 비키는 거리) |

### 1-3. 교정기 동작과 판정

| 용어 | 뜻 |
|---|---|
| **θ (gate 기준)** | 교정기가 "고칠지 말지" 점수 p_g를 내는데, p_g ≥ θ일 때만 교정을 적용한다. **run 1–3에서는 규칙에 따라 θ=0(항상 적용)이 선택됐다.** run 4의 θ 선택은 미룬 분석에 들어 있다. 단계 E는 규칙상 θ=0이다 |
| **θ 선택 규칙과 진행 예산** | OOF fold 0에서 "교정으로 잃는 EP가 **0.5점 이하**"인 θ 중 **가장 작은 값**을 고른다. 이 "0.5점"이 진행 예산이다. §5-2의 진행 손실(학습 벌점)과는 다른 것이다. 자세한 정의는 §6-0 |
| **감속 불감대 (dead zone)** | 감속 채널의 원시값이 양수 쪽에 있으면 감속 전용 자르기(min(c,0)) 때문에 교정도 기울기도 0이 되는 구간(§3-2) |
| **straight-through** | 순전파는 그대로 두고, 역전파에서만 잘린 구간에 작은 기울기(0.1)를 흘려 불감대에서 빠져나오게 하는 방법(run 2부터, §3-2) |
| **감속 생존율 (liveness)** | 디코딩된 감속 제어점 중 **하나라도 0보다 작은**(크기 문턱 없음) 초안의 비율. 0%면 감속 채널이 죽은 것이다 |
| **P1 / P2 / P3, PASS** | 단계 T의 판정 지표와 결과. §6-0에 정의 |
| **사전 등록** | 결과를 보기 전에 판정 기준과 설정을 규칙 파일에 적어 두는 것. 각 수정은 **그 run의 결과가 나오기 전에** 기록했다. 단, 수정 3·4는 앞 run의 dev 결과를 본 뒤 결정했다(§10-2) |
| **"warm-up"** | 이 문서에서 서로 다른 세 가지를 가리킨다. **LR warm-up**, **grad-balancer warm-up**, **GT 초안 구간**. 비슷해 보이는 **KD 비율 ramp**도 있다. 넷을 §8-7 그림에 겹쳐 보였다 |

## 2. 왜 이 실험인가

### 2-1. 출발점: 진단 결과 (report 30–33)
- navtest에서 PARA-SSR(interaction_final)이 충돌(NC)로 실패한 **279건**을 분석했다.
- **279 = 정지 물체 149 + 움직이는 물체 119 + t=0에 없던 물체 11** (report 33. 부딪힌 물체의 t=0 GT 속도가 0.5 m/s 미만이면 "정지").
- **정지 물체가 원인인 149건:** 그중 79–91건은 모델 **자신의** 인지 결과로 만든 안전 필터로도 피할 수 있었다. 즉 인지는 했는데 planner가 반영하지 못했다.
- **움직이는 물체가 원인인 119건:** "현재 정보가 완벽하면" 고쳐지는 경우는 14–24건뿐이다. 미래 예측 문제가 크다. teacher 검출 + 등속 예측으로는 17/119로, 모델 자기 예측(44)보다도 낮았다.
- **교정의 가치:** 이미 낸 궤적을 장면을 보고 고치는 필터가 PDMS를 84.88에서 85.66으로 올렸다(report 31).
  - 84.88은 report 31의 분석 파이프라인에서 같은 interaction_final을 다시 채점한 값이다. 공식 평가값은 84.87(0.8487)이고, 이 문서의 기준선은 84.87이다.

### 2-2. 사용자가 정한 조건
1. **aux teacher가 정말 필요하다는 것을 보여야 한다.** 예측값을 가져다 쓰는 구조라면 GT를 쓰면 되므로 teacher가 필요 없다.
2. **어디가 KD인지 분명해야 한다.**
3. **KD는 E2E를 처음부터 학습하는 동안 적용한다.** 학습이 끝난 모델을 finetuning하는 방식은 안 된다.
4. **선행 연구가 있고 논문화할 수 있어야 한다.**
5. **학습된 E2E 모델에 의존하는 단계는 빼고, 협업자(kyungmin, byounggun)가 이미 한 실험과 겹치지 않아야 한다.** kyungmin님은 readout KD(효과 없음)와 GT critic을, byounggun님은 teacher BEV planner와 feature KD를 했다(`report/collaborator_audit/`).

### 2-3. 아이디어: 교정 KD
- **teacher 교정기:** teacher 조감도를 보고 "이 초안은 이렇게 고쳐라"를 내는 작은 모델을 먼저 학습한다.
- **E2E 학습 중 KD:** PARA-SSR에 붙인 student 교정기가 teacher 교정기의 교정량을 따라 배운다.
- **조건 1(teacher 필요성)에 대한 답은 두 비교로 한다.**
  - 단계 T: 장면을 안 보는 교정기(R_none)와 비교
  - 단계 E: GT 벌점만 쓴 E1과 비교
- **무엇을 고치리라 기대하나 (진단과의 연결)**
  - 인지는 했는데 계획에 반영되지 않은 **정지 물체 충돌**(149건 중 79–91건)
  - **도로 이탈**(DAC)
  - 앞차와의 **간격 부족**(TTC)을 감속으로 고치는 것
  - 움직이는 물체의 미래 행동은 teacher도 모른다(teacher 조감도는 t=0 정보). 그 부분은 미래 GT를 쓰는 GT 벌점이 맡는다.
  - 단계 T에서도 R_T의 우위는 종방향 유형(L-const, ignore-brake, creep, cv)에서 나왔다(§6-5).

### 2-4. 비슷한 기법과의 관계

| 기법 | 무엇을 하나 | 우리와의 관계 |
|---|---|---|
| **score loss** (SafeDrive, Hydra-MDP, WoTE, kyungmin v2) | 후보 궤적마다 공식 점수(시뮬레이터 라벨)를 **예측**하도록 학습하고, 가장 좋은 후보를 **고른다** | 우리 GT 벌점은 점수를 예측하지 않고, **궤적 자체의 벌점을 직접 줄인다** |
| **VAD planning constraint**, kyungmin **feasibility(feas_gt)** | GT로 만든 안전 비용을 planner 출력에 직접 건다. feas_gt는 EPDMS +0.33, seed 1개 | 우리 **GT 벌점과 같은 계열**이다. 그래서 GT 벌점은 기여가 아니라 student의 task loss이자 비교 기준(E1)이다 |
| **DistillDrive, PlanKD** 등 planner KD | GT·특권 정보 planner의 출력이나 feature를 증류한다 | 우리는 **교정 판단**을 증류하고, teacher 필요성을 GT-only 대조(E1)로 따로 검증한다 |

## 3. 교정기 (refiner)

### 3-1. 하는 일
- **입력:** 초안 하나(4초 궤적), ego 상태(속도, 가속도, 명령), 장면 조감도.
- **출력:** 초안에 대한 **교정량**. 새 궤적이 아니다.
- 교정이 0이면 원래 초안이 **비트 단위로 그대로** 나온다. 그래서 "안 고쳐도 되는 초안은 건드리지 않는 법"을 배우기 쉽다.

### 3-2. 출력 12개 값의 정의와 이유

| | 감속 6개 | 옆 이동 6개 |
|---|---|---|
| 정하는 것 | 초안 속도에서 **얼마나 뺄지**(dv, m/s)를 시간에 따라 나타낸 곡선 | 초안 **경로에서 옆으로 몇 m 비킬지**(d, m)를 경로를 따라 나타낸 곡선 |
| 곡선 | 0–4초 3차 B-spline, 매듭 0, 0.8, 1.6, 2.4, 3.2, 4.0초 | 초안 경로 길이를 0–1로 정규화한 3차 B-spline, 매듭 0, 0.2, …, 1.0 |
| 제어점 | 8개(c_0–c_7). **앞 2개는 0으로 고정**, 나머지 6개가 출력으로 정해진다 | 8개(e_0–e_7). **앞 2개는 0으로 고정**, 나머지 **6개**가 출력 |
| 범위 | 교정이 **더하는** 가속도 변화 δa가 −4 ~ +2 m/s² (초안 대비. 교정 후 궤적의 전체 감속도 한계가 아니다). 결과는 항상 dv ≤ 0 (감속 전용) | \|d\| ≤ 2 m (왼쪽이 +) |

- **감속 채널의 계산 순서 (불감대가 생기는 이유)**
  1. 네트워크 원시값 z(6개) → 미분 제어점 Q_1–Q_6 = A·tanh(z) (z<0이면 A=4, z≥0이면 A=2 m/s²)
  2. Q를 적분해 속도 제어점 c를 만든다(c_0 = c_1 = 0).
  3. 감속 전용이므로 **c ← min(c, 0)** 으로 자른다.
  - z가 양수 쪽에 있으면 c>0이 잘려 0이 된다. 이때 교정도 기울기도 0이다. 이것이 **불감대**다.
  - run 1에서는 두 교정기 모두 모든 초안에서 여기 빠졌다(z_lon>0이 100%).
  - run 2부터는 **straight-through**를 쓴다. 순전파는 그대로 min(c,0)이고, 역전파에서만 잘린 구간(c>0)에 기울기 0.1을 흘린다. 0.1은 train 데이터만으로 V1–V3 세 후보 중 규칙으로 골랐다(수정 3). 추론 때는 쓰지 않는다.
- **앞 2개 제어점을 0으로 고정한 의미**
  - 감속: dv(0) = 0, da(0) = 0. 교정 궤적은 **초안과 같은 속도·가속도로 시작**한다.
  - 옆 이동: d(0) = 0, d'(0) = 0. 교정 궤적은 **초안과 같은 위치·방향으로 시작**한다.
  - **고정된 것은 제어점이지 자세(pose)가 아니다.** t=0 직후부터 곡선은 초안에서 벗어날 수 있다. 0.5초 지점부터 교정이 반영된다.
  - 매듭 간격을 0.5초로 줄이는 변형(제어점 11개, 자유 9개)은 나중의 ablation 후보다. 지금 바꾸면 teacher 교정기부터 다시 학습해야 한다.
- 교정기의 원시 출력(z, w)을 **디코더**가 tanh로 제한해 위 제어점으로 바꾼다. 한계(4 m/s², ±2 m)를 정확히 지키는 것도 디코더다(학습할 파라미터 없음).
- **이렇게 정의한 이유**
  - 부드럽고 실제로 달릴 수 있는 교정만 나온다.
  - 학습할 숫자가 적다.
  - 실패 유형이 둘로 나뉘기 때문에 종·횡을 분리했다. 충돌·TTC는 **감속**으로, 도로 이탈은 **옆 이동**으로 주로 고친다.
  - 감속만 허용한 이유: 가속을 허용하면 진행 점수를 위해 위험하게 빨라질 수 있다. 또 **NC 실패에서는** 실제 E2E 궤적이 대부분 사람보다 빨랐다(4초 거리 비 중앙값 1.16). 전체 장면으로 보면 오차는 대략 대칭이다(비 p5 0.82 / p95 1.27, 0.9 미만 12.7%, 1.25 초과 5.7%). 느린 초안은 이 교정기로 고칠 수 없다.
- **옆 이동은 좌우 회전량이 아니다.** 초안 경로를 따라가면서 옆으로 평행 이동하는 양(Frenet 횡 오프셋)이다.
  - 초안이 우회전이면 교정 후에도 우회전이고, 그 경로에서 비켜 갈 뿐이다.
  - 방향 변화는 옆 이동의 결과로 조금 생긴다. 디코더가 곡률 한계도 지킨다.
- **추가 출력:** "고칠지 말지" 점수(gate, p_g) 1개. θ=0이라 실제로는 쓰이지 않는다. 단계 E에서는 gate loss도 없다.

## 5. GT 벌점: 무엇을 기준으로 궤적을 평가하나

### 5-1. 무엇에 대보나
- **평가 대상:** 고친 궤적. 0.1초 간격 41점으로 촘촘히 만들고, 우리 차 사각형을 씌운다.
  - 뒷바퀴 축 기준 **앞 4.05 m, 뒤 1.13 m, 폭 2.30 m**. (차 길이의 절반 2.588 m, 뒷바퀴 축→차 중심 1.461 m에서 계산)
- **기준(GT, 채점에만 쓰고 교정기 입력에는 넣지 않음)**
  1. **미래 물체:** 주변 모든 물체의 실제 미래 위치·크기·방향. 0–5초, 0.1초 간격, 360°. 로그에서 추출했다. metric cache의 물체 다각형과 비교한 모서리 최대 오차는 **7.6e-6 m**다(1,279장면).
  2. **도로 지도(SDF):** 각 지점이 주행 가능 영역에서 몇 m 안쪽(+)인지 바깥(−)인지.
     - SDF 자체는 LQR로 추적한 footprint 기준 공식 DAC와 **548/550** 일치한다.
     - 벌점이 실제로 쓰는 원시 41점 궤적 기준으로는 무작위 장면에서 97.3% 일치, recall 0.684다. 차이는 SDF가 아니라 LQR 추적 때문이다(§5-3).
  3. **경로 중앙선 + 공식 기준 planner(PDM-Closed)의 진행 거리**
  4. **원래 초안**
  5. **현재 속도·가속도**

### 5-2. 항목별 기준

| 벌점 (가중치) | 대응 지표 | 기준 | 벌점을 주는 경우 |
|---|---|---|---|
| 충돌 (1) | NC | 매 0.1초 같은 시점의 실제 물체와 간격 **≥ 0.15 m** | 부족한 만큼. 움직이는 물체(차·보행자·자전거) 1, 정지 물체 0.5 가중. 우리 차 중심에서 진행 방향으로 1.3 m 넘게 뒤에 있는 물체와, 사람 궤적도 겹치는 물체는 제외 |
| TTC (1) | TTC | 교정 궤적의 각 시점에서 **그 시점의 속도·방향으로 0.3·0.6·0.9초 앞으로 민 차체**와 그 시점 물체의 간격 **≥ 0.15 m** | 부족한 만큼 |
| 도로 이탈 (1) | DAC | 차의 네 모서리가 모두 도로 경계에서 **0.05 m 이상 안쪽** | 모서리마다 부족한 만큼 |
| 진행 손실 (2) | EP | **min(원래 초안의 진행 거리, PDM-Closed 진행 거리)보다 덜 가지 않을 것** | 부족분 ÷ max(PDM 거리, 5 m). "무조건 멈추기"로 벌점을 피하는 것을 막는다 |
| 승차감 (0.1) | C | 가속도 −4.05 ~ +2.40 m/s², 횡가속 4.89, 회전 속도 0.95, jerk 4.13 등 **공식 한계** | 넘은 만큼 |
| 수정량 (0.1) | – | 필요 이상으로 바꾸지 말 것 | 교정량 크기에 비례 |

- **진행 손실의 핵심:** 초안이 PDM-Closed보다 멀리 가면(예: "더 빨리 가기" 교란), **PDM 수준까지 감속해도 벌점이 없다.** 이 성질 때문에 감속 교정이 가능하다.
  - 식: L_prog = relu(min(P(τ0), P_pdm) − P(τ1)) / max(P_pdm, 5 m). P는 경로 중앙선을 따라 잰 진행 거리다.
- 모든 항목은 "기준선을 넘은 만큼" 커지는 미분 가능한 형태다. 충돌·TTC·도로 이탈은 softplus(부드러운 hinge), 진행 손실은 relu, 승차감은 relu², 수정량은 L1이다. 그래서 감속이나 옆 이동을 조금 바꾸면 벌점이 어느 쪽으로 변하는지(기울기)가 바로 교정기에 전달된다.
- **학습 방식:** 교정기는 정답 궤적을 따라 하지 않고 **이 벌점을 줄이는 방향으로** 학습된다. "사람 궤적으로 되돌리기"가 목표가 아니다. 빨라진 초안이라도 안전하면 그대로 두는 것이 정답이다.

### 5-3. 기준값의 근거와 한계
- **여유값 선택:** train 데이터에서 공식 채점과 대조해 미리 정한 규칙으로 골랐다(`m8_recheck/`, `ttc_select/`).
  - 조건: 공식 실패 검출(A1) ≥ 70%, 사람 궤적 오경보(A2) ≤ 2%, 벌점상 해소 → 공식 해소(A3) ≥ 0.60.
  - sweep 1순위(도로 여유 0.10 m)는 confirm 풀에서 도로 오경보 2.26%로 탈락했다. 그래서 사전에 정한 대체 규칙으로 **도로 여유 0.05 m**를 썼다(수정 2).

| 벌점 | 공식 실패 검출 (A1) | 사람 궤적 오경보 (A2) | 벌점 해소 → 공식 해소 (A3) | 출처 풀 |
|---|---|---|---|---|
| 충돌 | 91% | 0.95% | 0.61 [0.53, 0.68] | confirm (842장면 / 91 log) |
| 도로 이탈 | 90% | 0.95% | 0.60 (sweep 풀 0.55) | confirm |
| TTC | 88% | 0.6% | – | sweep (800 log) |

- **한계**
  - 공식 채점기는 제어기(LQR)로 따라간 경로로 채점하고, 우리는 궤적 그대로를 잰다. 그래서 공식 실패의 약 10%는 벌점에 잡히지 않는다.
  - **더 큰 격차는 A3다.** 벌점상 충돌이 해소된 경우 중 공식 NC도 해소되는 것은 약 61%, 도로는 55–60%다. "벌점 감소"가 곧 "PDMS 상승"은 아니다.
  - DDC(역주행)는 벌점이 없다. dev 원래 초안의 DDC 실패율은 0.003%이고, 두 교정기 모두 교정 후 0%다.

| **P1** | 교정 후 PDMS 차 (R_T − R_none), dev 초안 평균 | 점 (0–1 PDMS × 100) | + 면 R_T 우위 |
| **P2** | NC 또는 TTC 실패율 차 (R_none − R_T) | %p | + 면 R_T가 실패를 더 줄임 |
| **P2 비열등** | DAC, DDC 실패율에서 R_T가 R_none보다 0.5%p 넘게 나쁘지 않을 것 | %p | – |
| **P3** | 새 실패율 차: 교정 전에 통과하던 초안이 교정 후 NC·DAC·DDC·TTC·C 중 하나라도 실패하는 비율. R_T가 0.5%p 넘게 나쁘지 않을 것 | %p | – |
| **sanity** | 적어도 한 교정기가 "교정 없음" 대비 PDMS를 유의하게(CI 하한 > 0) 올릴 것. 성립해야 측정으로 인정 | – | – |

| 판정 | 조건 | 뜻 |
|---|---|---|
| **PASS** | P1 하한 > 0 **그리고** P2 하한 > 0 **그리고** P3 비열등 | teacher 교정기가 KD teacher 자격이 있다 |
| **EQUIVALENT** | P1, P2의 CI가 ±0.2점 / ±0.5%p 안 | 현재 설정에서 teacher 우위 없음 |
| **WORSE** | R_T가 유의하게 나쁨 | 원인 진단 먼저 |
| **INCONCLUSIVE** | 그 외 | seed 추가나 dev 확대. 결론 없음 |

- **통계:** log 단위 짝지은 bootstrap 10,000회, 95% CI. seed가 1개라 CI는 데이터 변동만 반영하고 학습 변동은 반영하지 않는다.
- **θ 선택과 진행 예산**
  - 규칙: OOF fold 0에서, 교정으로 잃는 EP가 **0.5점 이하**인 θ 중 가장 작은 값.
  - run 1: 모든 초안의 EP로 쟀다. 그런데 공식 EP는 NC·DAC·DDC 실패 시 0이 되므로, 실패를 고치면 오히려 EP가 올라 예산이 무의미했다.
  - run 2부터(수정 3): 교정 전후 모두 NC·DAC·DDC를 통과한 초안의 EP 손실(순수 감속 비용)로 잰다.
  - 결과: run 1–3 모두 θ=0. run 3의 EP 손실은 R_T 0.08점, R_none 0.15점으로 예산 안이다.

### 6-2. 초안 은행 (장면당 13개)
- 사람 궤적을 **일부러 망가뜨린** 초안으로, 단계 E의 GT 교란 초안도 같은 생성기를 쓴다.
- **13개라는 수는 튜닝한 값이 아니라 설계 가정이다.** 원본 1 + 작은 교란 3 + 큰 교란 8 + (원래는 학습된 student 초안 1 → 등속 직진으로 대체)
- 원본 외 12개 슬롯은 **7개 유형**이다(작은 교란·더 빨리 가기는 각 3슬롯, 옆으로 밀기 2슬롯).

| 슬롯 | 종류 | 교란 | 크기 |
|---|---|---|---|
| 0 | 원본 | 사람 궤적 그대로 | – |
| 1–3 | 작은 교란 | 고칠 필요 없는 수준 | 가속 **0 ~ +0.2 m/s²**(빨라지는 쪽만), 옆 ±0.3 m 이내 |
| 4–6 | 더 빨리 가기 (L-const) | 0–2초 중 한 시점부터 가속을 더함 | +0.2 ~ 1.3 m/s², jerk ≤ 2 |
| 7 | 브레이크 무시 | 사람 감속의 30–100%를 무시 | 사람이 1 m/s 이상 감속한 장면만 (아니면 "더 빨리") |
| 8 | 조금씩 나감(creep) | 거의 멈춘 장면(사람의 4초 이동 거리 < 2 m)에서 전진 | +0.3 ~ 1.0 m/s² (아니면 "더 빨리") |
| 9–10 | 옆으로 밀기 | 경로 중간부터 부드럽게 옆으로 | 0.3 ~ 1.5 m, 좌우 대칭 (사람 경로가 3 m 미만이면 "더 빨리") |
| 11 | 복합 | 더 빨리 + 옆으로 | 위 범위 (같은 대체 규칙) |
| 12 | 등속 직진 (cv) | 현재 속도로 처음 방향 직진 | 만들 수 없거나 사람 궤적과 거의 같으면, 위치는 사람 궤적 그대로 두고 방향만 조금 틀어진 초안(hdrift) |

- **크기의 근거:** 실제 E2E 오류. 실제 student와 사람의 차이를 가속도로 환산하면 99.7%가 ±1 m/s² 안이고, 4초 시점 옆 오차는 97%가 2 m 안이다.
- **제약:** 시작점 연속(첫 구간 속도 차 −0.8 ~ +0.6 m/s), 운동 한계, 사람이 실제로 간 8초 경로 사용(외삽 없음. creep만 경로가 모자라면 중앙선이나 직선으로 연장). 느려지는 교란은 만들지 않는다(감속 전용 교정기로 되돌릴 수 없어서).
- **라벨:** 모든 초안을 공식 채점기로 채점했다. 배치 채점은 궤적 8,500개에서 단일 채점과 불일치 0이었다. 실패율은 12%(TTC 포함 18%)다.

### 6-3. 학습 방식 (모든 run 공통)

| 항목 | 값 |
|---|---|
| 배치 | 장면 8개 × 초안 13개 ≈ 104개 |
| 최적화 | AdamW, lr 3e-4, cosine, weight decay 0.01, gradient clip 1.0 |

## 8. 단계 E: E2E 학습 중 교정 KD (지금 진행 중)

### 8-1. 실험 조건

| | 구성 | student 교정기의 학습 신호 | 상태 |
|---|---|---|---|
| **E0** | PARA-SSR v1 (`interaction_final`) | – (교정기 없음) | 이미 있음. navtest PDMS 84.87 (30 epoch `last.ckpt`) |
| **E1** | PARA-SSR + student 교정기 | **GT 벌점만** | 보류. E2 뒤에 같은 설정으로 |
| **E2** | E1과 동일 | **GT 벌점 + KD (run-4 R_T, R_M)** | **학습 중** |

- **E1 − E0:** 교정기 + GT 벌점(구조 보완)의 효과. 알려진 기법 계열이라 기여가 아니다.
- **E2 − E1:** 논문의 핵심 주장이고, "GT만 쓰면 되지 왜 teacher냐"에 대한 답이다. 다만 정확히는 **"GT 벌점에 두 teacher 교정기의 KD를 더한 효과"**다. 여기에는 다음이 함께 들어 있다.
  - teacher의 장면 정보
  - KD라는 "촘촘한 교정 target" 형식 자체
  - 교정기 loss 증가(r=1에서 약 2배)와 그에 따른 BEV 기울기 증가
  - CUDA 난수 재설정 1회(teacher 로딩 때)
  - 장면 정보가 원인이라는 주장은 **단계 T(R_T > R_none, 섞기 대조)로만** 뒷받침된다. 단계 E에서 이를 가를 대조군은 없다(§11 후보).
- **E2 − E0:** 둘이 섞여 있어 KD 효과를 따로 말할 수 없다. E1이 나오기 전까지의 잠정 비교다. E0와 E2는 완전히 같은 조건도 아니다(§10-7).

### 8-2. 어디로 학습 신호가 흐르나

| 학습되는 부분 | PARA-SSR 자체 loss | GT 벌점 | KD |
|---|---|---|---|
| student 교정기 | ✗ | ✅ | ✅ |
| 조감도를 만드는 부분 (이미지 backbone → BEV encoder) | ✅ (balancer 적용) | ✅ (배율 1.0, balancer 밖) | ✅ (배율 1.0, balancer 밖) |
| planner (초안 τ0 생성) | ✅ | ✗ (초안 기울기 차단) | ✗ |
| 검출·지도·모션 head | ✅ | ✗ | ✗ |
| teacher 교정기 R_T, R_M | – (고정, 평가 모드, checkpoint에 저장 안 됨) | ✗ | ✗ |

- **PARA-SSR 자체 loss:** planner 모방(가중 2), 검출(1), 모션(1), 지도(1).
  - **grad balancer**가 공유 BEV로 가는 기울기 비중(기울기 norm 비)을 plan 0.4 / det 0.3 / map 0.3으로 맞춘다. 계획(plan)은 기준이라 배율이 늘 1이고, 검출(+모션)과 지도의 BEV 기울기 배율만 1e-5–1 사이에서 낮춘다. warm-up(5,300 micro-batch ≈ epoch 1.0) 동안은 배율을 모두 1로 둔다.
  - E0도 같은 balancer를 쓰고, warm-up이 끝나는 시점도 같다(E0는 10,600 micro-batch, GPU 2장 기준으로 역시 ≈ epoch 1.0).
  - 교정기 loss(GT 벌점 + w·KD)는 **balancer 계산이 끝난 뒤에 더한다.** 즉 balancer의 조절 대상이 아니다.
  - 기울기 clip: 교정기 파라미터만 먼저 1.0으로 자르고, 그 뒤 전체를 35로 자른다.
- **planner로 막은 이유:** planner가 "교정기가 고치기 쉬운 초안"을 내도록 서로 맞춰지는 것과, 모방 loss와의 충돌을 피하기 위해서다.
- **조감도를 1.0으로 연 이유:** teacher의 우위는 조감도 정보에서 나왔으니, student 조감도도 교정에 필요한 정보를 배울 수 있게 했다.
- **실측 비중 (E2, 2026-09-30 00:30 측정, epoch ≈ 1.78)**

| 구간 | loss 값 비중 (vshare) | BEV 기울기 비중 (gshare) | E0 loss의 BEV 기울기 norm |
|---|---|---|---|
| epoch 0 (balancer warm-up 중) | GT 벌점 약 0.75%, KD 약 0.04–0.12% | 교정기 몫 중앙값 **약 0.2%** | 약 0.03 |

  - **PARA-SSR loss 비교 (E0와 같은 global step)**

### 8-3. 교정기에 들어가는 초안 (장면당 1개)

| 구간 | 초안 | 이유 |
|---|---|---|
| **epoch 0–4 (GT 초안 구간)** | **GT 교란 초안 100%.** 사람 궤적(GT)을 초안 은행의 원본 외 12개 슬롯(7개 유형) 중 하나를 균등하게 뽑아 망가뜨림. 조건이 안 맞으면 §6-2의 대체 규칙 | 초반 PARA-SSR 초안은 거의 무작위라 교정을 배울 재료가 아니다. teacher도 본 적 없는 분포다 |
| **epoch 5–29** | 장면마다 독립적으로 50% 확률로 **GT 교란 초안**, 나머지는 **PARA-SSR 초안(τ0)** | τ0는 추론 때 실제로 고칠 대상이라 적응이 필요하다. 후반에 τ0가 좋아져 배울 게 없어지는 것은 GT 교란 초안이 막는다 |

- **교란 실패 시:** 교란이 무효이면 교란 없는 궤적을 쓴다(GT 초안 구간에는 GT 궤적, 이후에는 τ0).

- **같은 초안을 셋에게:** student와 두 teacher가 **같은 초안**을 받는다. GT 벌점과 KD 모두 그 초안 기준이다.
- **단계 T와 다른 점:** 장면당 초안이 13개가 아니라 **1개**다. 교정기 계산이 초안 수에 비례해서 13개면 E2E 학습 시간이 몇 배로 는다.

### 8-4. KD: R_T, R_M이 어떻게 가르치나
```
같은 장면, 같은 초안
  ├→ student 교정기 (PARA-SSR 카메라 조감도) → 교정량 12개 s
  ├→ R_T (고정, BEVFusion LiDAR+카메라 조감도) → 교정량 12개 t_T
  └→ R_M (고정, ReSMap 카메라+위성 조감도)     → 교정량 12개 t_M

L_T = mean |s − t_T|,   L_M = mean |s − t_M|
  (12개 = 감속 제어점 c_2–c_7 [m/s, 감속 전용 자르기 후] + 옆 이동 제어점 e_2–e_7 [m])
KD  = ½·L_T + ½·L_M
```
- **비교하는 값:** 원시 출력(z)이 아니라 **디코딩된 실제 교정량**이다.
  - teacher는 감속이 필요 없는 초안에서 원시 출력을 크게 포화시킨다(+7 ~ +13).
  - 원시값을 따라 하면 student의 감속 채널이 불감대로 밀려 죽는다.
- **L_T와 L_M은 같은 식이다.** 비교하는 teacher만 다르다. 따로 재는 이유는 두 가지다.
  - 로그로 student가 어느 teacher에 가까운지 볼 수 있다(`kd/l1_0`=R_T, `kd/l1_1`=R_M).
  - "합의한 만큼만 따라 배우는" 성질이 생긴다. 두 teacher가 같은 쪽을 가리키면 그쪽으로 끌고, 엇갈리면 student가 둘 사이 어디에 있든 KD 힘이 0이다(이때는 GT 벌점이 결정).
- **KD 신호가 실제로 0이 아닌 비율 (학습 전 오프라인 감사, 초안 64개, student가 교정 0인 상태)**
  - 옆 이동: 두 teacher 값이 엇갈리는 비율 37.5%.
  - 감속: **KD 기울기의 89.8%가 0.** 감속이 필요 없는 초안에서 두 teacher가 모두 교정 0을 내기 때문이다.
  - 출처: `report/refiner_E_code_audit/refiner_audit_teacher.json`. 학습 중 실측값이 아니다.
- **알려진 성질:** 단위가 다른 12개 값(m/s 6개, m 6개)을 같은 비중으로 평균한다. 학습 중 L1은 감속 쪽이 조금 더 크다(epoch 1, R_T 기준 감속 0.12 vs 옆 0.09). 그래서 KD가 감속에 조금 더 무게를 둔다.

### 8-5. GT 벌점과 KD의 비율
- student 교정기 loss = GT 벌점 + w × KD
- w = r × (GT 벌점의 이동평균 ÷ KD의 이동평균)
  - 이동평균: momentum 0.99, bias 보정, GPU 4장 평균, 기울기 차단. KD 이동평균의 하한 1e-4.
  - w 상한: 100.
- **효과:** **이동평균 기준으로** KD 항의 크기가 GT 벌점의 r배가 된다. r=1(epoch 5부터)이면 평균적으로 1:1이다. 고정 숫자를 쓰지 않는다.
  - **개별 step에서는 같지 않다.** 예: epoch 1.780의 한 step에서 w·KD 0.049, GT 벌점 0.321(r=0.36)이다. 바로 옆 step에서는 둘이 거의 같기도 하다(0.054 vs 0.050).
  - 시험 실행에서 잰 고정 가중치 19.14는 쓰지 않는다. 학습 중 비율이 변하기 때문이다.
- **r:** epoch 0에서 0, epoch 5에서 1까지 선형으로 올린다(micro-batch마다 갱신). 초반에 가중치가 튀는 것을 막기 위해서다. 측정 시점(epoch 1.78) r ≈ 0.36, w ≈ 0.32.
- **"1:1"과 "50:50"은 다른 것이다.**
  - 1:1 = GT 벌점 : KD의 loss 크기 (이동평균, r=1 이후)
  - 50:50 = GT 교란 초안 : E2E 초안의 비율 (epoch 5 이후)

## 10. 한계와 위험 (한곳에 정리)
1. **seed 1개:** 학습 편차를 모른다. 단계 T에서 두 arm에 똑같이 적용한 목표 변경 하나로 P2가 1.6%p 움직였다(run 3 효과의 두 배).
2. **결과를 본 뒤의 설계 변경:** TTC 벌점, 불감대 수정 등. 각 변경은 다음 run 전에 기록했지만, 결정 자체는 이전 결과를 보고 내렸다.
3. **teacher in-sample (단계 E에 주는 영향)**
   - BEVFusion은 navtrain, ReSMap은 train_logs로 학습됐다. 그래서 단계 E의 85,109장면 전부에서 teacher 조감도가 실제보다 좋다(검출 recall dev 0.893 vs navtest 0.846, 지도 IoU 0.944 vs 0.887).
   - teacher 교정기도 그중 15,693장면(약 18%)을 학습에 썼다.
   - 따라서 학습 중 KD target은 test 때 teacher가 낼 품질보다 좋다. 추론에는 teacher가 없으므로 navtest 평가의 타당성에는 영향이 없다. 해석상의 문제다.
4. **합성 초안의 모양 단서:** 사람 궤적 교란 초안은 모양만 보고 되돌리는 요령을 허용한다. 그래서 단계 E에서 τ0를 절반 섞는다.
5. **teacher는 실제 E2E 초안을 본 적이 없다.** 학습된 student 초안(원래 슬롯 12)을 빼면서 teacher는 사람 궤적 교란으로만 학습·평가됐다. 가장 가까운 대체물인 등속 직진(cv)에서 navtest P2는 +3.74%p였다. run 4 R_T는 OOF에서 교란 없는 사람 궤적의 5.9%에도 감속을 건다(`run4/liveness_oof_T.json`). epoch 5 이후 τ0에 대한 teacher 교정량의 타당성은 검증되지 않았다.
6. **GT 벌점과 공식 채점의 차이:** 공식 채점은 궤적을 제어기로 따라간 경로를 쓴다. 벌점은 공식 실패 약 10%를 놓치고, 벌점상 해소의 약 40%는 공식으로는 해소되지 않는다(A3 약 0.6).
7. **E0와 E2의 조건 차이:** GPU 수·accumulate(데이터 분할 순서가 다름), E0는 validation 켜고 학습, 코드 버전, 추론 때 교정기 유무, BEV가 교정기 기울기를 받음(epoch 1 이후 큼, §8-2). 교정기를 끄고 같은 4 GPU 설정으로 다시 학습한 E0'는 없다. 그래서 E2 − E0는 참고값이다.
8. **E2 단독으로는 KD 효과를 말할 수 없다.** E1이 필요하다. E2 − E1도 "장면 정보"의 효과인지, KD 형식·loss 크기의 효과인지는 가르지 못한다(§8-1).
9. **teacher 두 개의 평균:** 효과가 LiDAR(BEVFusion)에서 오는지 위성 지도(ReSMap)에서 오는지 구분할 수 없다. 합의 성질과 단위 혼합은 §8-4.
10. **기본 모델이 v1:** 팀의 v2(88.14)보다 약 3점 낮은 기준선이다. 또 kyungmin report 22 §14에 따르면 v1은 heading 출력에 설계 결함이 있어, 평가 때 heading을 경로 방향으로 다시 계산하면 학습 없이 84.87 → 85.93이 된다. 우리 디코더는 교정 궤적의 heading을 초안 heading에 맞춰 두므로 이 결함이 남는다. 교정기의 DAC 이득이 이 결함을 메우는 것인지 가르려면 heading 보정 전후를 함께 보고해야 한다(미정).
11. **student 감속 생존율이 teacher의 절반이고 `zdead`가 커지는 중:** §8-9.

## 12. 자주 묻는 질문

### 12-1. 전체 구조
- **Q. 지금 E2E 모델을 학습하고 있나?**
  - 단계 E의 E2가 PARA-SSR을 처음부터 학습 중이다.
  - 단계 T에서는 E2E를 학습하지 않았고, 작은 교정기만 학습했다.
- **Q. 단계 E가 쓰는 teacher는 자격 시험을 통과했나?**
  - 엄밀히는 아니다. PASS를 받은 것은 run 3 R_T다. 단계 E teacher는 run 4 R_T·R_M이고, 감속 생존율 검사만 통과했다. R_none 대비 판정(C1/C2)은 미뤘다(§7).
- **Q. kyungmin님의 PARA-SSR v2를 포함하나? 왜 v1인가?**
  - 포함하지 않는다. v1 기반이다.
  - 규칙 파일에는 이유가 적혀 있지 않다(개정 3에 "Base model: PARA-SSR v1"만 있다). 정황상 이유: E0 레시피와 모든 epoch checkpoint가 있어 같은 조건 비교가 가능하다. v2는 anchor 256개 중 점수 head로 고르는 구조라 교정기를 어디에 붙일지부터 새로 설계해야 한다.
  - v1 이득이 v2로 옮겨진다는 근거는 아직 없다(§11-3의 5).
  - v2의 score loss(anchor 점수 예측)와 feasibility는 §2-4에서 비교했다.

### 12-2. 데이터와 판정
- **Q. dev는 무엇인가? val set인가?**
  - 역할상 held-out validation이다. navtrain에서 log 단위로 따로 떼어 낸 8,000장면이다.
  - NAVSIM의 `val_logs`와는 다른 세트다.
  - 조건 간 판정에 쓰고, 설정 선택은 train 안(inner-val, OOF fold)에서만 했다.
- **Q. 다른 log인데 왜 dev가 학습과 "겹치나"?**
  - log는 drive를 잘라 만든 구간이라, 같은 drive의 이웃 구간이 학습 쪽에 있을 수 있다. dev 장면의 94%가 그렇다. navtest는 drive 단위로도 겹치지 않는다(§1-1, §6-1).
- **Q. dev PASS가 도시 전반에서 성립하나?**
  - navtrain 풀의 65.5%가 Las Vegas다. dev에서 P2 순효과의 99.7%가 Las Vegas에서 나왔고, 나머지 세 도시 합계 P2는 +0.01 [−0.26, +0.30]이었다.
  - navtest에서는 Las Vegas 외 합계 P2가 +0.52 [0.23, 0.81]로 확인됐다. 도시별로는 Pittsburgh(CI가 0 포함)와 Singapore가 유의하지 않다. P1은 모든 도시에서 양수다.
- **Q. 단계 T의 PDMS 0.896과 E0의 84.87은 무엇이 다른가?**
  - 0.896은 합성 초안을 교정한 뒤의 평균(0–1)이고, 84.87은 모델 궤적의 navtest 점수(×100)다. 서로 비교하는 값이 아니다(§1-2).

### 12-3. 교정기
- **Q. 교정기는 무엇을 기준으로 학습되나?**
  - 정답 궤적을 따라 하지 않는다. GT 위에서 매긴 벌점(§5)을 줄이는 방향으로 학습된다.
  - teacher 교정기도 같은 방식으로 학습됐고, 입력만 teacher 조감도였다.
- **Q. B-spline 제어점 8개 중 앞 2개를 고정하면 처음 1초는 못 고치나?**
  - 아니다. 고정된 것은 제어점이지 자세가 아니다. 교정은 초안의 속도·가속도(감속), 위치·방향(옆 이동)과 같게 **시작**할 뿐이고, t=0 직후부터 곡선이 벗어날 수 있다(§3-2).
  - 매듭 0.5초(제어점 11개, 자유 9개) 변형은 나중의 ablation 후보다. 지금 바꾸면 teacher 교정기부터 다시 학습해야 한다.
- **Q. 옆 이동은 회전량인가?**
  - 아니다. 초안 경로에서 평행하게 비키는 거리다(§3-2).
- **Q. 감속 "4 m/s² 이내"는 전체 감속도 한계인가?**
  - 아니다. 교정이 초안에 **더하는** 감속도의 한계다(§3-2).
- **Q. student 교정기는 단계 T 가중치로 시작하나?**
  - 아니다. 처음부터 학습한다. 몸통 초기값은 단계 T seed 0과 같지만 학습된 가중치는 불러오지 않는다(§8-6).
- **Q. student 조감도는 teacher 조감도와 같은 격자인가?**
  - 같다. PARA-SSR `bev_embed`는 그대로 S grid다. 뒤집기는 BEVFusion에, 전치는 ReSMap에만 필요하다. student 입력은 LayerNorm으로 정규화한다(§3-3).
- **Q. 교정기 학습은 얼마나 했나?**
  - 단계 T: 최대 40 epoch, inner-val 6 epoch 조기 종료. run 3 기준 R_T 38 epoch(best 31), R_none 36 epoch(best 29).
  - 단계 E: E0과 같은 30 epoch이고, 교정기는 PARA-SSR과 함께 학습된다.
- **Q. 13개 초안의 근거는? 단계 E도 13개인가?**
  - §6-2. 튜닝한 값이 아니라 설계 가정이다.
  - 단계 E는 계산 비용 때문에 장면당 1개다.

### 12-4. GT 벌점과 KD
- **Q. GT 벌점은 score loss와 같은가?**
  - 다르다. score loss는 후보 궤적의 공식 점수를 예측해 고르고, GT 벌점은 궤적을 직접 고친다.
  - 다만 GT 벌점은 VAD·kyungmin feasibility와 같은 계열이라 기여가 아니다. 기여는 KD(E2 − E1)다.
- **Q. GT 벌점으로 고친 실패가 공식 채점에서도 고쳐지나?**
  - 충돌은 약 61%, 도로 이탈은 55–60%다(A3, §5-3). 벌점 감소가 곧 PDMS 상승은 아니다.
- **Q. GT 벌점과 KD는 어디로 가나?**
  - 둘 다 똑같이 student 교정기와 조감도 쪽으로 간다(배율 1.0, grad balancer 밖).
  - planner와 다른 head에는 가지 않는다.
- **Q. PARA-SSR 자체 loss는 무엇이고 교정기 loss와 어떻게 합쳐지나?**
  - planner 모방(2), 검출(1), 모션(1), 지도(1). grad balancer가 BEV로 가는 비중을 plan 0.4 / det 0.3 / map 0.3으로 맞춘다. 교정기 loss는 그 뒤에 더해진다(§8-2).
- **Q. 왜 epoch 1부터 교정기의 BEV 기울기 몫이 뛰었나?**
  - balancer warm-up(5,300 micro-batch ≈ epoch 1.0)이 끝나 PARA-SSR loss의 BEV 기울기가 약 20배 줄었는데, 교정기 loss는 balancer 밖이라 그대로였기 때문이다(§8-2). 대응은 결정 대기 중이다(§8-9).
- **Q. 같은 벌점으로 배운 teacher를 따라 하는 KD가 왜 따로 도움이 되나? (E2 − E1로 확인할 가설)**
  - GT 벌점은 선을 넘을 때만 신호가 생기지만, teacher는 모든 초안에 구체적인 교정량을 준다.
  - GT 벌점은 현재 관측으로 알 수 없는 미래까지 벌하지만, teacher 교정은 t=0 인지로 낸 판단이라 따라 배우기 현실적이다.
  - 카메라 조감도만으로 찾기 어려운 "장면 → 교정" 매핑을 teacher가 더 좋은 입력으로 먼저 찾아 둔다.
  - 단, 초기에는 감속 KD 기울기의 약 90%가 0이다(§8-4).
- **Q. E2 − E1이 양수면 무엇이 증명되나?**
  - "GT 벌점만 쓰는 것보다 이 두 teacher 교정기의 KD를 더하는 것이 낫다"까지다. 장면 정보가 원인이라는 것은 단계 T로만 뒷받침된다. 가르려면 E2-none, E2-shuffle 같은 대조가 필요하다(§8-1, §11-3).
- **Q. "GT를 쓰면 되는데 왜 teacher냐"에 E1만으로 답이 되나?**
  - E1은 "GT loss"와 비교할 뿐, "GT를 입력으로 받는 teacher"(R_GT)와는 비교하지 않는다. teacher 조감도가 in-sample이라 GT에 가깝기도 하다. 그래서 이득이 "촘촘한 교정 target 형식"에서 오는지 "aux 센서"에서 오는지는 E2 − E1로 가를 수 없다. 규칙 파일에는 R_GT가 "추가하면 보고"로만 적혀 있다. 돌리지 않으면 주장 범위를 줄여야 한다.
- **Q. R_T와 R_M 중 어느 쪽 덕분인지 알 수 있나?**
  - 현재 설계로는 없다. 단일 teacher 조건(E2-T, E2-M)이 필요하다. 로그의 `kd/l1_0`, `kd/l1_1`은 student가 어느 쪽에 가까운지만 보여 준다.
- **Q. epoch 5 이후 절반인 τ0에서도 teacher 교정량을 믿을 수 있나?**
  - 검증되지 않았다(§10-5). 가장 싼 확인은 E0의 navtest τ0에 run-4 teacher를 적용해 채점하는 것이다(§11-3). 현재 로그는 τ0 초안과 GT 초안을 나눠 기록하지 않는다.
- **Q. 학습 장면의 τ0는 실패가 드문데(navtrain NC 0.70% vs navtest 2.30%, report 32), student가 test의 τ0 오류에 맞게 배우나?**
  - 부분적으로만. 절반은 실제 오류 분포에 맞춘 합성 초안이고, 나머지 τ0는 대부분 이미 안전하다. 평가 때 τ0 실패 장면과 통과 장면을 나눠 보고하고, 통과 장면에서 새로 생긴 실패 수를 따로 보는 것이 방법이다(아직 계획에 넣지 않음).
- **Q. 19.14는 무엇이었나?**
  - 시험 실행 한 시점의 GT 벌점/KD 비율로 정한 고정 가중치였다.
  - 학습 중 비율이 변하는 문제 때문에 버리고, 이동평균 기준 자동 맞춤으로 바꿨다.
- **Q. "매 step 1:1"인가?**
  - 아니다. 이동평균 기준으로만, 그리고 r=1이 되는 epoch 5부터 1:1이다. 개별 step은 다를 수 있다(§8-5).
- **Q. 초반에 KD를 끄나?**
  - 끄지 않는다. 대신 epoch 0–5에 걸쳐 비율 r을 0에서 1로 올린다.
  - 같은 기간(GT 초안 구간)에는 teacher가 아는 분포인 GT 교란 초안만 쓴다.

### 12-5. 평가와 통계
- **Q. 어떤 checkpoint를 평가하나?**
  - 마지막 epoch(`last.ckpt`, epoch 29)다. validation이 없어 고를 근거가 없고, E0 84.87도 `last.ckpt` 값이다. 규칙 파일에 적혀 있지는 않다(§8-8).
- **Q. E2 − E1이 얼마면 "KD가 효과 있다"고 하나?**
  - **정해지지 않았다.** 사전 등록된 것은 주 비교와 통계 방법뿐이고, PASS 문턱은 없다. E2 숫자를 보기 전에 정할지는 사용자 결정이다(§11-1).
- **Q. seed 1개인데 bootstrap CI는 무엇을 뜻하나?**
  - navtest 장면·log 표본 변동만 반영한다. 학습 변동(seed, DDP 순서, 난수 재설정)은 반영하지 않는다. CI가 0을 넘어도 재현이 보장되지 않는다. PARA-SSR의 seed 간 편차는 **측정한 적이 없다**(§11-1).
- **Q. E2가 E0보다 낮으면 어떻게 하나?**
  - **사전에 정한 행동은 없다.** 원인을 가를 후보만 §11-2에 적었다.
- **Q. E0와 E2는 같은 조건인가?**
  - 레시피(데이터, epoch, 유효 배치, optimizer step 수)는 같지만 완전히 같지는 않다(§10-7). 그래서 주 비교는 같은 코드·설정으로 돌리는 E2 − E1이다.
